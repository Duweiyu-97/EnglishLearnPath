## 2026-08-25：取消数据目录选择后无法再次选择

### 现象

首次点击“选择或创建文件夹”后关闭目录选择窗口，再次点击时可能只出现空白 PowerShell 窗口；目录选择窗口不再正常出现，页面按钮也一直处于等待状态。

### 根因

旧实现通过 `powershell.exe` 启动 WinForms `FolderBrowserDialog`。取消或关闭窗口后，子进程在部分 Windows 环境中没有可靠退出，导致 `/api/data/select-directory` 请求一直未完成。前端为了避免重复点击而禁用了两个选择按钮，因此看起来无法再次选择。

### 修复

- 移除数据目录选择流程对 PowerShell 和 WinForms 的依赖。
- 启动器直接调用 Windows Shell 原生目录选择 API。
- 历史资源选择窗口曾改用 Windows 原生 API；该资源模块现已移除。
- 将当前浏览器窗口设为选择器所有者，避免选择器落到浏览器后方。
- 用户点击“取消”或关闭窗口时，原生 API 立即返回取消状态；页面 `finally` 逻辑恢复两个按钮，之后可以重复打开。
- 不改变原目录，也不会因为取消操作创建或写入数据文件。

### 验证清单

1. 首次打开选择器后点击“取消”，页面显示“已取消选择”。
2. 再次点击能够重新打开选择器。
3. 连续使用窗口右上角关闭三次，每次都能再次打开。
4. 选择新文件夹后正常创建 `EnglishLearnPath-data.json`。
5. 取消前后不存在由启动器遗留的 `powershell.exe` 子进程。
6. 历史资源选择窗口测试已随资源模块移除。

### 发布策略

原计划先进入本地候选包统一收集问题；实际试用确认该问题会阻塞后续所有目录相关操作，因此作为阻断性修复发布 `v0.3.1`。后续非阻断性问题仍集中验证后再统一发布。

## 2026-08-25：录音与转写操作分离

### 调整

- 移除右侧独立的“开始浏览器转写”按钮。
- 左侧主按钮统一控制录音与实时转写：开始录音时同步启动语音识别，结束录音时同步停止。
- 转写结果实时写入右侧文字稿，可继续手动修改、保存或交给 AI 评价。
- 浏览器不支持语音识别或识别临时失败时，录音功能仍可继续，并显示明确提示。
- 新建或载入另一条口语记录时清理上一段仅驻留页面的录音，避免音频与文字稿错配。

### 技术边界

Chrome/Edge 的 Web Speech API 监听实时麦克风，不能直接读取已经生成的 WebM 录音文件；因此这里采用“录音过程中同步转写”，而不是录音完成后的离线音频转写。
