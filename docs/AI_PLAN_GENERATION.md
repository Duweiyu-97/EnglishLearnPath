# 考前计划分批生成

- 每次只生成一个阶段的七天循环，日期窗口由本地程序确定，不让模型修改。
- 每个阶段、拆分和重试均携带相同的全程框架、全部阶段目标、已确认的前面阶段及本阶段前半批的实际任务。后续尚未生成的阶段提供目标约束，不虚构后文。上下文最多四个七天模板，不无限拼接聊天记录。
- 完成后检查阶段日期连续、星期顺序完整并覆盖考试日。提示词要求内容承接和训练递进；自动检查不能保证模型对学习内容的语义判断永远正确。
- 输出截断时按星期顺序拆小批次，例如 7 天拆成 3 + 4 天；单日仍截断就停止，不无限增加额度。
- 每个请求最多 6000 输出 token；整个操作最多 20 次请求、5 分钟。正常情况下每阶段一次请求。拆分及重试可能增加 API 费用。
- 临时服务错误或格式错误，每批最多重试一次；鉴权失败立即停止。数值类型、范围、星期顺序及天数必须完整通过检查。
- 水平描述各最多 200 字，重点与限制最多 2000 字。超长输入提示精简，不静默截掉用户要求。
- 中途结果只在当前操作内存中组装，不写入学习数据。所有阶段完成并且用户未改变计划条件或旧计划进度，才排队提交。
- 与其他学习记录共用保存队列；写盘成功后才在内存和页面中替换计划。保存阶段不可取消，避免把已提交写入误报为取消；生成阶段可以取消。
- 本地自动化覆盖阶段日期边界、递归拆分、缺失/重复星期、错误字段、单日超限、总请求上限、连续失败、取消、重复点击、输入变化、写盘失败和并发保存。相同测试在 Windows 与 macOS CI 执行。

测试使用合成模型响应，不保证每种第三方模型都能遵循协议。最终失败时会保留旧计划并明确提示；不会将半份计划当作成功结果。
