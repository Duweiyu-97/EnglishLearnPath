# 考前计划生成流程

1. 先计算今天到考试日的周期、每日分钟数、累计可用小时和强度；水平差距按用户描述记录，不推断测评分数或承诺达标。
2. 根据周期划分大阶段，再将每个大阶段展开为连续的小阶段，每个小阶段最多七个实际日期，最后逐日生成独立任务。日期从今天一直覆盖考试日，末段允许不足七天。
3. 每次调用携带全程框架、大阶段目标、所有小阶段窗口、此前阶段的任务数量摘要、最近小阶段的具体任务及本阶段已确认内容。后续阶段通过目标约束衔接，不虚构尚未生成的结果。
4. 输出截断时进一步拆小当前日期范围，单日仍超限则停止。临时错误、格式错误每批最多重试一次。总请求预算为小阶段数量乘七加十，最多800次；生成时限随周期增长，最高60分钟。一次最多规划三年，超出时明确提示，不截掉后续日期。
5. 每个日期校验字段、顺序、任务范围、每日估算时间、至少40%复盘比例；考试日只热身。校验全部日期连续、无重复且覆盖考试日。
6. 所有小阶段完成后才排队保存；写盘成功后更新页面。生成失败、取消、条件或进度改变都不替换旧计划。生成期间不能切换数据目录、导入或清空数据；最终写盘阶段不可取消。
7. 数据保存为 scheduleVersion 2，首页和写作/口语页按实际日期读取。计划页按大阶段→小阶段→日期展开。旧版周模板和手动计划保持兼容，不自动修改旧记录。

长周期会产生更多 API 请求和费用；进度中显示当前请求量及上限。测试使用合成响应，覆盖一年、两年、三年完整日期、衔接、截断递归、错误字段、预算、取消、条件变化、写盘失败及并发保存。语义连贯性通过共享上下文和训练约束增强，不能保证所有第三方模型都始终正确理解要求。
